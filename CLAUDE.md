@AGENTS.md

## O projeto

Shop Studio: guia de TikTok Shop em formato de app para criadoras afiliadas no Brasil, com capítulos, assistente de IA, gerador de roteiros, checklist e resultados. É uma migração do "Shop Club" (feito no Enter.pro, Vite) para Next.js 16 + Supabase próprio + OpenRouter. A pasta irmã `../ShopStudio` é o original e é **somente leitura**: serve de referência, nunca escreva lá.

## Comandos

```bash
pnpm dev                     # http://localhost:3000  (NÃO use 127.0.0.1, ver Armadilhas)
pnpm test                    # vitest, só tests/**/*.test.ts
pnpm lint
pnpm build
pnpm db:start                # Supabase local (Docker)
pnpm supabase migration up   # aplica migrations novas SEM apagar dados
pnpm db:reset                # recria o banco do zero (APAGA dados locais)
pnpm db:types                # regera src/integrations/supabase/types.ts
```

Antes de dar uma tarefa por concluída: `pnpm test && pnpm lint && pnpm build` (todos limpos, sem avisos).

## Arquitetura (o essencial)

- **Páginas** em `src/app/**`, quase todas componentes cliente (`"use client"`), portadas do original. A sessão do Supabase fica no navegador (`localStorage`), sem `@supabase/ssr` nem middleware. **O navegador não fala com o banco:** do Supabase ele só usa o login (`supabase.auth`); todo dado passa por `api()` (`src/lib/api-cliente.ts`) → rota em `src/app/api` → Postgres direto (`db()` em `src/lib/db.ts`, `DATABASE_URL`).
- **Login por e-mail + senha** (`src/app/entrar/page.tsx`, `signInWithPassword`). Sem login social, cadastro público nem "esqueci a senha". **A conta só nasce pelo webhook** `POST /api/webhook/conta` (segredo `WEBHOOK_CONTA_SEGREDO` no `Authorization: Bearer`; CORS só para `WEBHOOK_CONTA_ORIGENS`), que chama `criarConta` (`src/lib/contas.ts`): usuário confirmado pela API admin, senha temporária aleatória, linha em `senhas_temporarias` e `entitlement` (`origem = 'compra'`) numa consulta só; se o banco falhar, apaga o usuário. O webhook genérico **devolve a senha temporária** na resposta. **Applyfy:** `POST /api/webhook/applyfy` (token no corpo, `APPLYFY_WEBHOOK_TOKEN`; só `TRANSACTION_PAID` de `APPLYFY_PRODUTO_IDS`; idempotente por `transaction.id` em `compras_applyfy`) chama `criarConta` e manda o e-mail de acesso pela Resend (`src/lib/email.ts`), sem devolver nem logar a senha.
- **Senha temporária:** vale 24 h (`VALIDADE_SENHA_TEMPORARIA_MIN`, era 30 min até o e-mail de acesso; `estadoDaSenhaTemporaria` → `"pendente" | "expirada" | null`, pelo `now()` do banco). Enquanto houver linha em `senhas_temporarias`, `autenticar()` responde 403 e a guarda mostra `DefinirSenha` (`GET /api/acesso` devolve `trocarSenha` **só** enquanto houver linha; depois da troca o campo some). Webhook chamado de novo para conta com linha pendente gera outra senha e renova o prazo; sem linha, 409. `POST /api/senha` (só com a linha pendente) troca pela API admin e apaga a linha. **A troca derruba as sessões abertas**, então a tela entra de novo com a senha nova. A marca **não** vai no `app_metadata`/`user_metadata`: eles viajam no JWT e aparecem no navegador.
- **Minha conta:** `/app/conta` + `PATCH /api/conta` (`autenticar()`). Nome vai para `user_metadata.full_name` e `profiles`. O TikTok (link do perfil, normalizado por `perfilDoTiktok` em `src/lib/video.ts`; vazio tira) vai só para `profiles.tiktok`, sem pedir senha, e o `GET /api/conta` o devolve para a tela (ele não está no token). **E-mail e senha só mudam com a senha atual** (`conferirSenha` em `src/lib/supabase/admin.ts`, login do Supabase que encerra a própria sessão); não tire isso, senão um token roubado toma a conta. O e-mail novo entra já confirmado (os modelos de e-mail não têm link). Depois de e-mail/senha a tela entra de novo; validações em `src/lib/entrada.ts` (`EMAIL`, `senhaValida`).
- O primeiro login cria o perfil em `ensureProfile` (`src/hooks/use-auth.tsx` → `POST /api/perfil`, que só grava se não existir).
- **Menu lateral redimensionável (2026-11-11):** no computador, a alça na borda direita do menu (`role="separator"` em `app-shell.tsx`) estreita o menu de `MENU_MAX` 272 px (a largura original, o máximo) até `MENU_MIN` 76 px; abaixo de 180 px (`menuCompacto`, em `src/lib/navegacao.ts`) ficam só os ícones, com o nome no `title`. Setas do teclado mudam 16 px, e o duplo clique volta ao máximo. A largura fica no `localStorage` (`shopstudio:menu-largura`), lida no `useState` inicial: o AppShell só monta no navegador, depois da guarda. O menu do celular (`Sheet`) não muda.
- **Guarda da área logada:** `src/app/app/layout.tsx` (login → troca da senha temporária → acesso → `AppShell`). Sem sessão, o destino vem de `destinoSemSessao` (`src/lib/navegacao.ts`): se a pessoa clicou em "Sair" (`saiu` no `useAuth`), vai para `/entrar` limpo; se a sessão caiu sozinha, vai para `/entrar?de=<página>`. Não volte a montar o `?de=` direto na guarda.
- **Regra de acesso:** `src/lib/access.ts` (`ACESSO_ABERTO_PARA_REVISAO`, `temAcesso`). Roda só no servidor (`autenticar()`); a tela recebe o sim/não de `GET /api/acesso`.
- **Rotas de IA** (`src/app/api/{assistente,roteiro}/route.ts`) passam por `autorizar()` em `src/lib/api-auth.ts`, que checa nesta ordem: env OpenRouter → token Bearer → `entitlements`. A função devolve uma `Response` de erro ou `{ apiKey, model, user, userId }`. As outras rotas usam `autenticar()` (token + senha já trocada + acesso) ou, só `perfil`, `acesso` e `senha`, `logada()` (só token). O webhook não usa token de aluna, e sim o segredo. Chame a OpenRouter sempre por `chamarOpenRouter()`, que injeta `PROVEDORES`.
- **Assistente:** prompt em `src/lib/assistente.ts`. O `BASE_PROMPT` (regras + resumo dos capítulos + transcrição + dossiê) vem **primeiro e é idêntico para todas as alunas**, para aproveitar o cache de prompt. Persona e capítulo vêm depois. A persona é a constante `PERSONA` (`src/lib/persona.ts`, `server-only`), que era a única linha da tabela `ai_config` até 2026-11-12: mudar = deploy. Não coloque nada variável antes do material. **Falha do provedor (2026-11-12):** a resposta só vale com `finish_reason: "stop"` e texto; 5xx, rede, evento de erro, stream cortado ou vazio mostram o aviso com "Tentar de novo" (`tentarDeNovo` em `use-ai-chat.ts`, reenvia a última pergunta sem duplicar a bolha), e a rota devolve o crédito. 4xx mostra a mensagem do servidor, sem botão. Com `OPENROUTER_PRESET`, o assistente chama `<modelo>@preset/<slug>` (o campo `preset` do corpo é ignorado), o system prompt do preset entra antes do nosso e a `PERSONA` sai. O roteiro nunca usa o preset (devolve JSON).
- **Treinamento da IA (só admin):** `/app/treinamento` + `/api/treinamento`, com toda função começando por `admin()` (`src/lib/api-auth.ts`), que roda o `autenticar()` e confere a tabela `admins` **no banco a cada chamada**. `admins` só muda pelo painel do Supabase. O `GET /api/acesso` devolve `admin: true` só para admin, e isso serve só para o menu. Fila em `treinamento`, sem `user_id` de aluna, com origem `mapeada | aluna | admin`. As conversas do assistente ficam em `treinamento_conversas`, procuradas sempre pelo par (`user_id` do token, `conversa` do navegador), e o `user_id` nunca sai nas rotas de admin. No `protecao.test.ts`, as rotas de admin ficam no conjunto `ADMIN` (aluna com acesso → 403).
- **Fichas de roteiro (treinamento do gerador):** aba "Roteiros" em `/app/treinamento` (`src/components/fichas-roteiro.tsx`), rotas `/api/fichas` e `/api/gatilhos`, todas com `admin()` antes de ler o pedido (estão no `ADMIN` do `protecao.test.ts`). **"Nova ficha" começa por um rascunho da IA:** a tela chama a `/api/roteiro` com `rascunho: true`. A rota confere `ehAdmin` no banco e, se for admin, não gasta créditos (mas grava em `ai_perguntas`) e põe o `RASCUNHO_BLOCK` (`src/lib/roteiro.ts`, depois das fichas, para não quebrar o cache), que pede `tipo` e `explicacao` (porquê e entonação por parte). Para a aluna, `rascunho` é ignorado. A prévia usa `PreviaDoRoteiro` (`script-generator.tsx`), a mesma tela da aluna; no 5×5 só troca a frase escolhida. "Escrever do zero" (botão ao lado do "Nova ficha") abre o formulário vazio. Lógica em `src/lib/fichas.ts` (tipos em `fichas-tipos.ts`): embedding **só de `produto — tipo`, em minúsculas** (`textoDaFicha`; a busca da aluna também vai em minúsculas; `POST /api/fichas/reindexar`, só admin, refaz todas); fichas com `exemplo_fixo` (até 6, `listarExemplosFixos`) entram em todo roteiro pelo `blocoDasFichas(..., fixas)`, depois dos gatilhos e antes das parecidas; `buscarParecidas` (≥ `LIMIAR_CARTAO` 0,70, até 3) para o cartão 1; `buscarDoMesmoJeito` (mesmo formato de `FORMATOS` + mesmo gatilho, sem as do cartão 1) para o cartão 2; `blocoDasFichas` (lista de gatilhos + fichas ≥ `LIMIAR_MODELO` 0,80) vai em `buildSystemPrompt(..., fichas)` **depois do dossiê**. O gerador devolve `gatilho` (normalizado por `gatilhoDaIa`) e `fichas`; `fichas` nunca vai para o roteiro salvo (`/api/roteiros-salvos` descarta). Sem nenhuma ficha indexada, `buscarParecidas` nem chama o embedding. Os cartões são `<details open>`: vêm abertos e a aluna fecha pelo título. Cada ficha leva as etiquetas de `porQueAparece` (`fichas-tipos.ts`: produto com %, mesmo formato, mesmo gatilho), e os links abrem em outra aba a página **Roteiros expert** (`/app/roteiros-expert`, `?ficha=<id>` abre e destaca uma), que lista todas as fichas com "Ver o porquê" por `GET /api/roteiros-expert`. A aluna escolhe quantas por linha (1 a 6, `colunasDaGrade`, no `localStorage`); com mais de 3 cartões de fato na linha (`colunasNaTela` pela largura da tela, os mesmos sm/lg/xl de `GRADES`; `abreEmPopup`) o cartão mostra só o gancho e o roteiro abre num pop-up (Radix Dialog), e o `?ficha=` abre o pop-up dela (`autenticar()`, `listarFichas` sem embedding nem autora). Os gatilhos só crescem (o "+"); gatilho com ficha não some (FK).
- **RAG no assistente:** `consultarExpert` (`src/lib/treinamento.ts`) gera o embedding da pergunta com as 2 anteriores (`textoParaEmbedding`, o mesmo formato ao indexar) e busca as 4 respondidas mais parecidas. `blocoDaExpert` usa os limiares: ≥ 0,9, a IA repete quase palavra por palavra; ≥ 0,7, as respostas entram como modelo; ≥ 0,6, só ligam as parecidas na tela. O bloco vai **no fim** do prompt (`buildAssistantSystemPrompt(..., expert)`). Se o embedding falhar, o assistente responde sem o bloco. No fim do stream, `registrarNaFila` grava a pergunta e a resposta, e resposta vazia ou cortada não entra. Embedding: `src/lib/embedding.ts`, 1536 dimensões, acoplado à coluna (trocar de modelo exige migration e indexar tudo de novo).
- **Créditos semanais (2026-11-12):** dois saldos por semana, **15 perguntas** e **7 roteiros** (`LIMITE_SEMANAL` em `src/lib/limite.ts`), sem acumular; **cada pedido gasta 1**, do tamanho que for; a semana começa no domingo à 0h de Brasília (`semanaSP`, UTC-3). Tabela `creditos_semana` (pk `user_id` + `semana` + `rota`): semana nova = linha nova, então o reset é sozinho. `reservarChamada` (`src/lib/api-auth.ts`) reserva 1 do tipo da rota numa consulta só (`on conflict … where gastos + 1 <= limite`; sem linha = 429 com `MSG_SEM_CREDITOS[rota]`) e grava em `ai_perguntas`. IA falhou, roteiro cortado ou sem JSON = `devolverCredito`. Admin (`ehAdmin`) não grava em `creditos_semana`. A tela (`useCreditos(tipo)`, `GET /api/creditos` → `{ restantes: { assistente, roteiro } }`) só avisa com 4 perguntas ou 2 roteiros restantes (`AVISO_COM_RESTANTES`) e trava abaixo de 1; admin recebe `{ ilimitado: true }`. Tokens e custo continuam em `ai_perguntas` via `comRegistroDeUso` (`src/lib/uso.ts`). Antes (2026-11-11) era um saldo só de 40, com meio crédito a mais por tokens; saiu.
- **Vídeos campeões (cadastro da admin):** abas na tabela `nichos` (`slug` pk, `rotulo`). **Ordem fixa** no `GET /api/nichos` (`ORDEM`, pelo slug): `moda-fitness`, `moda-feminina`, `beleza` ("Beleza e autocuidado"), `casa-e-cozinha`, `suplementos`; as outras depois, por `criado_em`. Abas criadas e apagadas pela admin em `/api/nichos` (`GET` com `autenticar()`, `POST`/`DELETE` com `admin()` **antes** de ler o corpo; o slug sai de `slugDe` em `src/lib/entrada.ts`; só apaga aba sem vídeo). Vídeos na tabela `campeoes` (FK `nicho` → `nichos.slug`) (`nicho`, `url`, `titulo`; único por `nicho` + `url`; o banco só aceita `https://www.tiktok.com/@perfil/video/<id>`). `GET /api/campeoes?nicho=` usa `autenticar()`; `POST` e `DELETE` usam `admin()`. A URL passa por `urlDoTiktok` (`src/lib/video.ts`), que tira a query; o link curto do celular (`vt.tiktok.com`/`vm.tiktok.com`, `linkCurtoDoTiktok`) é resolvido no `POST` lendo só o `Location` do redirecionamento (`redirect: "manual"`, 5 s), sem abrir a página. Na tela, o formulário e o "Remover" só aparecem com `isAdmin` (de `GET /api/acesso`). **O roteiro não traz mais vídeos** (2026-11-10): a busca na Brave, `videos_cache` e `campeoes_cache` saíram. Nada de scraping do TikTok (proibido nos termos); o vídeo toca no player oficial.
- **Prompt do gerador (`src/lib/roteiro.ts`, 2026-11-11):** **voz da Ana** obrigatória (vocativos, expressões, CAIXA ALTA, palavras esticadas, colchetes de cena, lista de frases proibidas), regras por formato (Música viral **sem fala**, "Texto na tela: …", 7 a 15 s; `duracaoDoFormato` em `src/content/formatos.ts` dá a duração na tela), ganchos de tipos diferentes com **fofoca só entre os 5** (nunca o gancho do roteiro) e **preço opcional** (`preco` no pedido, até 40; sem ele, nenhum valor). Continuam: nada que a aluna não informou (cor, tamanho, estoque, tempo de uso) e resultado como experiência, nunca garantia. Ficou de fora, por decisão: CTA sempre com urgência, "não repetir entre roteiros" (cada geração é independente), autoconferência no prompt e os exemplos com preço inventado.
- **IA escrevendo: perguntar antes de sair e retomar no F5 (2026-11-12):** no gerador (`escrevendo` em `script-generator.tsx`) e no assistente (`isLoading`), a mesma `useGuardaDeSaida` pergunta "Seu roteiro ainda está sendo escrito" / "A resposta ainda está sendo escrita" (continuar aqui / sair mesmo assim); no F5, o aviso é o do navegador. **O F5 retoma:** o navegador cria o `pedido` (uuid) e o guarda no `sessionStorage` (`src/lib/pedido.ts`: `lembrar`/`lembrado`/`esquecer`, chave `shopstudio:pedido:<tipo>`); a rota grava em `ai_perguntas.pedido` (`reservarChamada`), termina o trabalho mesmo sem a aluna (`after()` do Next; no assistente, `comRegistroDeUso` lê a OpenRouter até o fim mesmo com o stream da aluna cancelado e devolve `{ corpo, terminou }`) e grava em `ai_perguntas.resultado` o `{ status, corpo }` que teria devolvido (`guardarResultado`). Depois do F5, a tela chama `esperarPedido` → `GET /api/pedidos?id=` (`autenticar()`, `user_id` do token; 202 escrevendo, 404 nunca chegou ou a IA nem respondeu, 504 depois de 90 s sem resultado). O pedido só é esquecido com resposta de erro do servidor, ao salvar, ao abrir outro da biblioteca e **ao desmontar** (sair pelo app = descarta; o F5 não desmonta). Conexão cortada (`TypeError` do `fetch`; o próprio F5 corta) não esquece. No assistente, a conversa inteira fica no `sessionStorage` (sobrevive ao F5, some ao sair pela app ou em "Nova conversa"), e a resposta retomada chega inteira de uma vez. O rascunho de ficha da admin não manda `pedido`. **Três armadilhas achadas no navegador:** o que fica guardado leva o `userId` (`lembrar`/`lembrado`), senão, com a sessão caída, outra conta na mesma aba via a conversa da anterior; "Nova conversa" muda `vez` em `use-ai-chat.ts`, senão a resposta retomada atrasada entrava na bolha da pergunta seguinte; e no gerador, `esperado` guarda o pedido que a tela espera (abrir um da biblioteca o zera), senão o roteiro abandonado tomava o lugar do aberto quando ficava pronto.
- **Guarda de saída do roteiro (2026-11-11):** com um roteiro gerado e ainda não salvo (`salvo` em `script-generator.tsx`; aberto da biblioteca conta como salvo), `useGuardaDeSaida` (`src/hooks/use-guarda-de-saida.ts`) pergunta "Salvar o roteiro antes de sair?" (salvar e sair / sair sem salvar / continuar aqui). Pega: links do app (clique em captura no `document`, só `preventDefault`, para o `onClick` do `Link` ainda fechar o menu do celular; decide `destinoDoClique` em `src/lib/saida.ts`), botão voltar (uma entrada extra no histórico com a mesma URL; o `pushState` do Next copia o estado interno dele) e recarregar/fechar a aba (`beforeunload`, aviso do navegador). Saídas que não são link (aba "Ganchos", "Sair da conta", abrir outro roteiro da biblioteca) chamam `sair()` de `src/lib/saida.ts`. Apagar roteiro salvo pede confirmação. O pop-up é `Confirmacao` (`src/components/confirmacao.tsx`, Radix Dialog). **Não limpe estado no cleanup:** sem `cacheComponents`, a página desmonta e o estado some sozinho; cleanup é só para listeners, timers e inscrições.
- **Mural das alunas (2026-11-11):** `/app/resultados` + `/api/resultados`. A aluna publica resultado em uma linha (até 80), depoimento e, opcional, link de vídeo do TikTok (`resolverUrlDoTiktok` em `src/lib/video.ts`, o mesmo dos Campeões: limpa a query e resolve o link curto do celular); pelo menos depoimento ou vídeo. **O nome vem da conta** (`nomeDoPerfil` do token, ou "Aluna do Shop Studio"), nunca do corpo. Até 10 por dia, contados no próprio insert. **Fixar no topo é só da admin** (`PATCH` com `admin()`, no `ADMIN` do `protecao.test.ts`); o `POST` não grava `destaque`. Apagar (só a própria) pede confirmação. Na tela, todo cartão tem o tamanho do player do TikTok (`QUADRO`, 9:16, até 280 px; até 4 por linha a partir de `xl`). Com vídeo: o `VideoEmbed` e, embaixo, o resultado (título) e o depoimento. Sem vídeo: um quadro escuro com o resultado (título) em cima do depoimento, com "Ler mais". Por último, o nome da aluna, que vira link para o TikTok dela (`profiles.tiktok`, do `left join` no `GET`) quando ela o pôs em Minha conta.
- **Ganchos (banco + comunidade):** tabela `ganchos` (`categoria` `quebra | problema | curiosidade`, `texto` de 5 a 200, `comunidade`, `user_id` de quem registrou) e `gancho_notas` (uma nota 1–5 por aluna por gancho, pk `gancho_id` + `user_id`). Os 60 do antigo `hooks-textos.ts` entraram pela migration `20261110020000_ganchos` com `comunidade = false`. `/api/ganchos`: `GET` e `POST` com `autenticar()` (a aluna registra o dela, no máximo `GANCHOS_POR_DIA` = 10 por dia, contados no próprio insert); `PATCH` e `DELETE` com `admin()`, valendo para **qualquer** gancho. `POST /api/ganchos/nota` faz upsert da nota. O `user_id` do autor nunca sai nas rotas; a `minhaNota` usa o `userId` do token. Na tela (`hook-bank.tsx`), lápis e lixeira só com `isAdmin`. Em `/app/roteiros` a aba de ganchos vem primeiro e é a padrão; a aba fica na URL (`?aba=gerador`), então links para o gerador levam `?aba=gerador`. Os ganchos de aluna **não** entram em prompt nenhum.
- **Material da IA:** `src/lib/conhecimento/{transcricao,dossie}.md`, lidos do disco por `material.ts` (`server-only`). Eles entram no deploy pelo `outputFileTracingIncludes` no `next.config.ts`. Se criar outra rota que use o material, adicione-a lá.

## Convenções

- **Idioma:** textos de interface, mensagens de erro, comentários e commits em **português do Brasil**. Nomes de código podem misturar (`temAcesso`, `buildSystemPrompt`), então siga o padrão do arquivo.
- **Nome do produto:** sempre "Shop Studio". Nunca escreva "Shop Club", "shopclub", `club-videos`, nem nada do Enter (`enter.pro`, `@enter-pro`, `ENTER_`, `opentrust`).
- **Sem i18n:** os textos ficam direto no código.
- **Sem lógica de "dona/owner":** admin é só quem está na tabela `admins` (painel do Supabase), e o que é de admin no app é a página de treinamento e o cadastro de vídeos na aba de Campeões. Tabelas de admin (`admins`, `access_codes`, `chapter_videos`) só são escritas pela service role; `treinamento`, `nichos` e `campeoes` só pelo servidor, em rotas com `admin()`.
- **Segredos:** `SUPABASE_SERVICE_ROLE_KEY`, `DATABASE_URL` e `OPENROUTER_API_KEY` só em módulos com `import "server-only"`. Nunca importe `src/lib/supabase/admin.ts`, `roteiro.ts`, `assistente.ts` ou `conhecimento/material.ts` em componente cliente. Nunca leia, imprima ou commite o `.env.local`.
- **Testes** em `tests/`, espelhando `src/`, importando por `@/…`. Rotas são testadas com o banco falso de `tests/apoio/db-falso.ts` (mocks de `@/lib/db` e `@/lib/supabase/admin`), mais `@/lib/access`, `server-only`, `@/lib/conhecimento/material` e `global.fetch`. `tests/app/api/protecao.test.ts` acha **toda** rota sozinho e exige 401 sem token e 403 sem acesso; `isolamento.test.ts` confere o `user_id` de cada consulta. Testes nunca chamam a OpenRouter. Escreva o teste antes da mudança.
- **Visual (2.0, 2026-11-09):** layout novo com a **paleta original** (rosa + chocolate quente; não mude as cores sem a dona pedir). Tokens em `src/app/globals.css`, Tailwind **v3** (`tailwind.config.ts`), fontes Bricolage Grotesque (`font-display`), Instrument Serif itálico (`font-accent` / `.accent-word`, só para a palavra de destaque) e Plus Jakarta Sans (texto). ## Segurança (não desfazer)

Auditoria de 2026-11-04: ver a seção Segurança do README e o DEVLOG.
- **Só o servidor cria conta:** `[auth] enable_signup = false` (o e-mail fica ligado só para o login). Ligado, qualquer pessoa cria conta com a anon key (achado 1 da auditoria). Testado em `tests/supabase/config.test.ts`.
- **Supabase blindado** (`config.toml`, testado em `tests/supabase/config.test.ts`): realtime desligado, `jwt_expiry = 900`, `secure_password_change = true`, `sign_in_sign_ups = 10`, e os e-mails de recovery/magic_link/email_change/reauthentication usam `supabase/templates/sem-link.html` (sem link nem código). Não ponha `{{ .ConfirmationURL }}` nem `{{ .Token }}` de volta sem o serviço de e-mail próprio.
- **Webhook de conta:** o segredo é a proteção de verdade; a lista de origens só controla o CORS (um `curl` escreve o `Origin` que quiser). Nunca aceite o webhook sem `WEBHOOK_CONTA_SEGREDO`.
- **Créditos** contados no servidor por `reservarChamada` (`src/lib/api-auth.ts`), com a reserva atômica em `creditos_semana`. Nova rota de IA = nova `rota` + limite em `LIMITE_SEMANAL` (`src/lib/limite.ts`) + o valor no `check` de `creditos_semana.rota`.
- **Nada de texto livre do navegador no prompt de sistema** (vide `capitulo` → `getChapter`). **Única exceção:** o treinamento da IA. A pergunta de aluna (e a resposta da IA, se aprovada) só entra no prompt de outras alunas depois que uma admin responde ou aprova, e o editor pede para deixar a pergunta genérica e tirar o que for pessoal. "Responder" abre o editor já com a resposta da IA; não existe aprovação direta, sem passar pelo editor. Não crie caminho que leve texto de aluna ao prompt sem passar pela admin.
- **CSP** em `src/lib/seguranca.ts`. Domínio externo novo precisa entrar ali (`frame-src`/`connect-src`), e o `connect-src` nunca leva `*`.
- **URLs vindas de alunas** são validadas no banco: `success_cases.midia_url` só aceita vídeo do TikTok (`https://www.tiktok.com/@perfil/video/<id>`, restrição `not valid` desde 2026-11-11: os prints antigos continuam lá, e a tela os mostra só com o texto).
- **Conteúdo pago nunca vai no JavaScript público.** Capítulos (corpo), desafio e checklist ficam em arquivos `server-only` de `src/content`, registrados em `src/content/protegido.ts`, e saem só por `/api/conteudo/<nome>`, que passa por `autenticar()` (token conferido no Supabase + `temAcesso`). No navegador: `useConteudo(nome)` + `<ConteudoCarregando>`. Em `chapters.ts`, `hooks.ts` e `challenge.ts` ficam só índice, rótulos e tipos. **Conteúdo novo:** arquivo com `import "server-only"`, entrada no registro e tipo em `ConteudoProtegido` (`types.ts`). Nunca importe esses arquivos numa tela; o build falha se isso acontecer. Os **ganchos** ficam no banco (tabela `ganchos`) e saem só por `GET /api/ganchos`, com `autenticar()`.
- **Bucket `studio-videos` é privado:** arquivo só abre por URL assinada gerada no servidor (`/api/videos`, validade em `VIDEO_URL_VALIDADE_SEGUNDOS`).
- **Logada usa a plataforma, não o banco.** A Data API (PostgREST) fica **desligada** (`[api] enabled = false`; em produção, Project Settings → Data API), então ninguém vê tabela, coluna nem estrutura. No banco, `anon` e `authenticated` não têm privilégio nem política nenhuma (RLS ligado = nada), nem para objetos novos: não crie políticas nem grants para eles. A conexão do servidor é dona das tabelas e **não passa pelo RLS**, então o isolamento está no código: **toda consulta de dado de aluna filtra por `user_id = ${userId}`, com o `userId` do token, nunca do corpo**; compartilhado só o que as telas mostram (`success_cases` sem `user_id`, só `minha`; `chapter_videos`; `nichos` e `campeoes`, só rótulos e URLs públicas do TikTok). Rota nova = `autenticar()` + teste em `isolamento.test.ts`.

## Armadilhas conhecidas

- **`127.0.0.1` trava o app em dev:** o Next 16 bloqueia recursos de dev de outra origem e a página fica no loader. Use `localhost:3000`. O Supabase local também usa `localhost` como `site_url`.
- **Testar telas logadas:** crie a conta pelo webhook (`curl -X POST localhost:3000/api/webhook/conta -H "Authorization: Bearer $WEBHOOK_CONTA_SEGREDO" -d '{"email":"…"}'`) e entre com a senha devolvida. Se já houver um `next dev` rodando sem as variáveis do webhook, use `pnpm build && WEBHOOK_CONTA_SEGREDO=… pnpm start -p 3005`. **Apague os usuários de teste no fim.**
- **`overflow-x: clip`, não `hidden`, em `html`/`body`:** com `hidden`, o body vira contêiner de rolagem e o menu lateral `sticky` para de grudar. A altura cheia das telas usa `min-h-dvh`, porque não existe `#root` como no Vite.
- **Modelo com raciocínio:** o DeepSeek v4.1 Flash gasta tokens de saída "pensando". Por isso `max_tokens: 4000`, e não os 1400/700 do original, e a resposta com `finish_reason: "length"` vira erro claro.
- **Provedores:** `PROVEDORES` (`morph/fp8`, `deepinfra/fp8`, só fp8) vale **só para o modelo atual**. Trocar `OPENROUTER_MODEL` exige revisar essa lista; senão vem 404 "No endpoints found". O provedor oficial `deepseek` é bloqueado pela configuração de privacidade da conta (provedores que treinam com os dados). Não mude isso sem a dona do produto pedir.
- **`session_id` fixo prende o provedor:** testado e descartado. Ele grudou num provedor caro e o cache falhou. Use `provider.order`.
- **`useSearchParams`** exige `<Suspense>` em volta, senão o build falha.
- **`lucide-react` fixado em `^0.542.0`:** a 1.x removeu o ícone do Instagram usado em `challenge.tsx`.
- **`AGENTS.md`** é recriado pelo `next dev`. Commite-o, não apague.
- **`pnpm db:reset` apaga os dados locais.** Para migration nova, use `pnpm supabase migration up`.
